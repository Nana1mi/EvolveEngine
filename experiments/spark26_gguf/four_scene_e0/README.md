# 四场景 E0/E0 校准（实验室负载）

**目的：** 在同一个未改源码的诊断 E0 上，用四个不同的指标估计性能水平、进程间波动和评测成本。`a`、`b` 都是 E0，不是 Harness 实验臂。此目录不改变旧 QKV/FFN 诊断、正式协议或现网配置。

| 场景 | 每路输入 → 输出（token） | 同时到达的独立请求数 | 性能指标 |
|---|---|---:|---|
| W1 | 128 → 256 | 1 | 单路 `(N-1)/(t_last_token-t_first_token)` |
| W2 | 1024 → 256 | 1 | 同 W1；业务目标 40/50 tok/s 只与此口径比较 |
| W3 | 4096 → 128 | 1 | 计分取 `1/TTFT(s)`；对人报告 `TTFT(ms)`，从发送请求到首次收到一个生成 token，不是纯 prefill 时间 |
| W4 | 128、512、1024、2048 → 各 96 | 4 | 同时释放四条独立 HTTP 流；384 个输出 token / 首路发出到末路 `[DONE]` 的墙钟时间；每一波必须有服务端原生日志证明四路同时解码 |

- **冻结项：** `plan.json` 是上传前的运行计划，`bundle.sha256` 列出进入节点的文件。新基线沿用固定映像、模型、tokenizer 与 `gguf.py`；只把上下文、总 token 池和活动请求上限改为 8192 / 16384 / 4。使用原生 `/generate` 与合成 token ID，固定贪心、定长生成；不测聊天模板、自然 EOS、工具调用或真实流量。
- **计时：** 每次都是全新的容器/服务进程；每进程、每场景先暖 1 波，再计 3 波。场景顺序在同对内相同，对间更换；进程顺序 `a1,b1,b2,a2,a3,b3`。无 profiler，无候选源码，无跨容器 JIT 缓存挂载。客户端记录单调时钟、实际 token 数、结束原因核验及输出摘要；原生服务日志核对活动请求数，而不是把 SSE 帧当 token。冷启动和建容器耗费进入节点成本，但不计入稳态场景指标。
- **分析：** 每进程先取三波中位数。各场景报六个进程中位数的中位数及范围；噪声单位是三对独立服务进程。单场景报有符号对称差 `200*(B-A)/(B+A)`，方向以高为好（W3 用 `1/TTFT`）。综合分把四项 `B/A` 等权几何平均再减 1。两种百分比口径不混用；最大观察波动不是显著性阈值、SLO 或保证。原始回执另有每请求 E2E 时间、接收边界和 token 哈希；不包含业务文本。
- **复核：** 在本目录运行 `python audit.py <本次原始回执目录>`。它验证输入/原始文件哈希、运行顺序、实际调度容量、请求级重算、运行轮数与闭环清理，并输出 JSON。复核不连接节点、不使用 GPU。启动新测量则需独立授权、独占空闲节点并获取 GPU 锁。
