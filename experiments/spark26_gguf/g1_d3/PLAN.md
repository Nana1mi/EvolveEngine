# G1-D3：第 0 层分块执行与开发数值判据 v0（事前登记）

范围：所有数据均属开发。已看过 D2 的 A/B/C/D；现在登记规则，只对尚未执行的 C₀ 做前向检查，不能给 D2 结果贴盲验标签。不接触 G1-V、密封 Q/T 或正式 W，不做速度择优。

三次全新容器，固定顺序：未改动 E0 `anchor` → 仅第 0 层分块 `local0a` → 相同实现重启 `local0b`；每次 32 个已知 D2 前缀各取一个完整下一词分布。原始回执/前缀/向量编码与 D2 相同。使用相同镜像和只读权重、固定启动参数、单节点锁、无外网、每容器最多 360s。先核 anchor 与 D2 两次 E0 逐字节相同，再配对计算；两次 C₀ 均报告，不挑较优次。无缺失且两次 C₀ 向量完全一致才称重启复现。

目标层**固定第 0 层**，因为它是结构上的第一层，不按任何层的输出挑选。只在 `model.layers.0.self_attn.q_k_v_proj` 执行与 D2-C 完全相同的 K/packed-block 对齐分块和 FP32 求和，其余 27 层用已测精确 QKV。每个开发请求事后复核全部 28 个具名执行事件恰好各一次，0 层路径为 split，余者 whole；核输入摘要、请求 ID、M、执行源文件路径与哈希，不能用工具启动时声明代替。缺项不算低误差。两次重启应该产生同一待测源文件。若不满足，不试别的层来换取通过。

**位置 → 引擎规则（screen.py 已随 bundle 冻结）。** 以下是研究用途的候选概率误差约束，受已知 D2 数据启发，不是从业务清单推得，亦非正式 G1：每个位置 TV≤0.05；32 个位置至多 3 个 TV>0.02；E0 第一二名 log-prob 差≥1.0 时不允许 Top-1 翻转。两项 TV 值分别对应对任一 token 子集的概率质量偏移上界 5、2 个百分点。边界值计入允许侧；margin=1 属于大分差。低 margin 的翻转仍受 TV 两道门约束。完整输出 KL、Top-10 并集的最大 log-prob 误差、全词表误差作诊断；不另调 KL 线重复裁决。至少一个经核实的违例即可判超出该**开发数值约束**；证据不齐且无已知违例是不签收，不能按零收益。通过也只指这 32 个合成位置，不代表服务质量或所有输入正确。

比较：在新样例上检查规则是否允许真实、非零的局部浮点差异；对既有 D2 的 A/B/C/D 离线重放并标示为已见对照。C_all 保留为压力样例；没有先验业务容忍界限，不把它的达标/超标当作数学上对/错。若 C₀ 超界、无漂移、缺回执或跨重启不稳，保留反例，不在本轮调整规则。不以完成 D3 自动开启 V、Agent 自由先导或 W。
