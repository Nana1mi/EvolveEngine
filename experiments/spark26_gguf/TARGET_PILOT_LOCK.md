## 3. Q8_0 驻留审计

- **量化驻留不可交换。** 加载时或首次请求后把 Q8_0 权重永久解量为 BF16/FP16/FP32，或另存长期浮点副本、替换原量化权重或走等价旁路均判不合规。保留原生浮点张量（如 norms）和算子内部的短生命周期计算/解量临时量需分别记录，不与常驻副本混为一谈。
- E0 和候选均以固定 GGUF manifest 为基准，按融合投影和绑权规则记录 device、GGUF 类型、packed dtype/shape、唯一 storage 字节及共享关系；在模型加载后与预热/请求归宿后取快照，核对投影、绑权 embedding/head 和原生浮点组。检查模块参数、buffers、额外属性/缓存及稳态 CUDA 活跃分配，核查源码差异；只认文件名、dtype、进程总显存或 `named_parameters()` 不够。审计缺覆盖、缓冲归属未知或检测到违规即不放行正式候选，报告可观测范围和未归因分配。

## 4. 质量与计时分离

- 确定性小集：验证固定提交在原生 GGUF + 实际 attention 组合下的确定性/批次不变模式；用同一输入确认同批复测、服务重启、单请求 vs 经证实的真合批。固定采样与停止规则，检查 token 序列、长度、EOS/stop 及选定业务 API 行为。开关被接受不代表覆盖了所有算子；若 E0 自身不稳定，先定位或改为可验证的质量规范并登记，不能默许候选通过。
- 性能：用生产等效配置和另行冻结的负载，无 profiler/审计探针；质量另做同配置 E0/E0 标定后冻结容忍度，不直接使用旧 `KL ≤ 0.001`。先定义关键指标、单位、失败/重跑规则和可接受的质量界限，再看候选结果。合成 E0/E0 的独立单位是新进程配对而非请求；三个配对只报告观察波动，不从中宣称推断显著性或生产阈值。
- Chat SSE 计时先冻结业务口径：首个生成 payload（可为思考或工具）、首个答案 payload、最后 payload 与 `[DONE]` 分开；首个角色帧和 usage 帧不参与。SSE 帧数不是 token 数，不从它伪造 token TTFT/TPOT；需要真 token 时延时，另登记等效的可验证来源。`.108` 实测文本 stop、长度封顶、thinking 与工具四种流式契约通过，不替代生产负载重复计时。
