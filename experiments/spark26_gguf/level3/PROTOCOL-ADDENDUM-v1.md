# Level 3 启动前补充协议 v1

登记日期：2026-11-24。适用于 `spark26-level3-exploration-v2`，不改写原方案、`acceptance-v2.json` 或历史 P3 回执。以下是启动前的约束，不是新验收结果、付费授权或 GB10 使用授权。

## 1. 截断与恢复（A2、E2、F1）

采用**整条探索链最多一次有界异常恢复**，不按 Session 重置。已结算的 `generation_truncated` 或出站前的 `context_generation_window` 不是永久终止；清理旧 Pi 后可从经复核的检查点开启新 Pi。其他网络、Guest、Worker 故障沿用同一额度，只有故障类别允许恢复且外层已核对资源账和隔离清理时才准入。未能对账或未确认释放的 Worker 不开新段；若协议允许用保守预留结清，须显式标为不确定扣账。`usage_uncertain` 准入违规、安全违规或资源不足不靠恢复绕过。

- 已验收 Engine、已激活 Harness、可信事实和被登记的研究状态从检查点复核加载；不回放截断请求、不执行其残缺工具、不重放旧 Pi 对话。
- **已显式检查点化且基准绑定有效的 WIP 可恢复**，但仍作为草稿；未保存的工作树改动、临时文件和进程状态不会继承。
- 普通 Agent 主动换段独立登记，不耗异常恢复额度，也不重置账本或绝对截止时间。异常恢复额度耗尽时停止、保留证据，不把失败记成绩效零收益。

## 2. SGLang 时间边界和来源（B1、B3、F1）

**禁止探索 Agent 读取 SGLang 在 E0 之后的上游历史。** 源码可见范围是锁定 E0 对应的上游提交 `b2ce7f8811bc40fd0d67000030c22edbbe0f2a37` 及经可信外层确认属于它的祖先的提交，不按提交时间戳猜测，不跟随 `main`、分支或可变标签。E0 的实验室兼容 overlay 仍由仓库既有协议锁定。

限制适用于源码、diff、提交说明、PR/Issue、新版本文档，以及镜像、fork、缓存或文章转述中会暴露禁读 SGLang 实现的内容，也适用于搜索摘要。针对 SGLang 的材料无法建立版本来源时，不把原文、摘要或链接预览传给 Agent；登记拒绝原因。Research Broker 要在交付给 Agent **之前**做过滤，而不是只要求 Agent 不看。EvolveEngine 的验收答案和密封数据仍隔离。一般论文、技术文档及其他公开引擎可以研究；若材料转述被禁 SGLang 改动，则该部分同样不可见。

记录实际读取的 URL、固定版本或 Commit、内容哈希、许可与可验证的引用/复用关系。结果区分**有外部来源记录的实现/启发**与**未观察到直接参考的方案**；后者不是新颖性证明。若发现意外可见的禁读材料，保存事故证据并标记受影响结论，不把该轨迹写成独立发现。验收至少验证 E0、可证祖先可读；后续提交、未知版本、可变 ref、redirect/镜像及搜索摘要泄露被挡在 Agent 之前。

## 3. 墙钟、模型、GPU 分账（A1、F1）

`393216 / 156` 约为 **2,521 秒，即 42 分钟**。这是用两次约 8,192 推理 Token 的局部实测做的外推；不是长请求速率、上限达成承诺或墙钟预算充分性的证据。也不预判 12 小时中模型一定用掉多少。

分开记录全链墙钟、托管 API 等待/生成时间、GPU 节点独占/租用时间及 GPU 实际作业时间；亦单记编译、部署、诊断、Profiler、Quality、Measure。请求托管模型本身不消耗本地 GB10 计算，但若策略在等待期间继续独占节点，该期间仍计入节点占用。模型和节点记录可能重叠，不强行相加为总墙钟。12 小时墙钟和 12 小时节点上限是两个独立约束，不互相替代，也不是本次授权。

## 4. 构建选项与数值语义（C3、D2、D3）

在 §9.4 补列**通过快速数学、低精度或不安全构建选项改变数值语义，从而换取提速**。如 CUDA `--use_fast_math`、编译器 `-ffast-math`/`-Ofast`、改变舍入或 flush-to-zero、用近似内在函数替代计算。参数名是风险线索，不独立证明作弊，也不要求把满足冻结语义的候选一律拒绝。

- 保存实际生效的命令/参数、目标架构、构建产物与加载身份，不只检查 Agent 提交的参数声明；相同产物、实际计时配置须走门禁。
- 在开发门与独立 Q/T 分别覆盖预登记的数值敏感位置、近似平票/长上下文与目标模型适配的下游质量；在工装中预登记一个通过构建或执行设置实际改变语义且预期应拒的负控，不以伪造日志替代。
- 真实语义损坏按违规处理，观测缺失按证据不足；不在看到候选分数后调宽门槛。覆盖范围不等于对任意 Native/编译组合的正确性证明。

## 5. 传输证据边界（A1）

按现有 `v3_dev_rpc/exploration.json` 与代码，宿主至供应商的 **HTTP 读空闲是 1,800 秒**（还受发起时剩余墙钟约束），Relay 模型路由的 **Unix Socket I/O 是 900 秒**；工具路由是 390 秒。900 秒不约束 Relay 阻塞等待宿主 stdio 回帧的那段时间。宿主消费并校验完整 SSE 后才发带长度的回帧；Relay 再把**已缓冲、已核验**的响应按块写给 Pi。这不是边生成边把未核验内容分段转发给 Pi。

2026-11-24 的两个历史本地原始摘要均已重读，配置、出站上限与结果如下；这次未重跑：

## 6. 留出集保管、共审与启封（D1、F2）

**研究负责人（用户）与一位强模型共审**独立探索 Q/T，例如经用户选定的 Gemini。Codex 起草协议、固定评分和签收模板；研究负责人和独立模型审查覆盖、泄漏、分数语义与判定，研究负责人最终审批。共审不等于由模型服务商保管数据，也不等于授权现在调用该模型。

留出集由研究负责人或其明确指定的独立可信评估存储保管；实际保管位置和访问者由负责人在首次探索启动前确认。模型默认只看协议、覆盖清单、脱敏样例和可审计摘要；原始题目、标注、Prompt 或私有数据不自动出域，只有另行明确批准方式与可见范围后才提供给外部审阅服务。启动前须锁定与未来正式 W/B0/B2 分离的探索 Q/T、数据及评分脚本哈希，记录保管人、审阅者、访问策略和签收。最终交付封存后只由可信 Judge 解封执行；分数不回流给 Agent。当前尚未指定物理存储或完成共审，不签收 D1。

最终 Q 必须预登记适配目标模型的下游任务质量（例如数学推理、问答准确率）、固定评分代码及相对 E0 的可接受退化界线；由研究负责人和选定的强模型共审。开发门的 token 分布容差和通过回执不能代替这项最终检查。与受审探索分开的首次无留出工程探索不访问 Q/T，不可签收 D1/F2 或主张最终任务质量通过。
