# G1-D4：第 0 层同输入归因（事前登记）

只做开发诊断。沿用此前镜像、模型权重和运行参数，不开启 G1-V、P3 或 W，不变更概率判据 v0。单个新鲜无网络容器，GPU 唯一锁，整次容器最多 360 秒。不会把这个诊断补丁作为 Engine 提交。

只看第 0 层，从 D3 已见 32 个位置取编号 0、1、24、25：前两个为各长度最早编号，后两个包含已知大漂移点 25 与相邻另一长度。故不能视作盲验。对同一 GPU 激活 `x` 和同一 packed Q8_0 权重计算 `whole`、`left`、`right` 及 BF16 部分结果先扩为 FP32 后求和再舍回 BF16（与 D3 一致）；真正回给前向的是 `whole`。记录未经过矩阵乘法的输入身份、实际代码、全矩阵差异，以及两个半块的源块范围。证明诊断没有改变输出：四个 endpoint 全词表向量应匹配 D3 E0 锚点，前缀摘要一致。

每位置固定激活行 `0, M//2, M−1`，输出通道固定 `0,1,127,2047,2048,2559,2560,3071`，覆盖 Q/K/V 边界。参考实现用独立 Python `struct` 按每 32 元素的 2-byte little-endian FP16 scale 和 32 个有符号 byte 解权重，用 `math.fsum` 累加 FP64 点积，同时记录 whole、左右半块与各自参考值。CUDA 路径取实际固定镜像的 dispatcher 源和输入形状，不假定 torch/内核行为；独立 FP64 参考是未额外量化激活的数学点积，允许某个 kernel 内部实施的激活量化导致偏差，不把任何偏差直接定义为缺陷。

分开报告：① whole 与 split 在相同输入上是否已不同；②偏差在理论 BF16 部分积各自舍入下能解释多少，或是否已在 half/whole 与相应点积参考之间出现；③最终输出只对 whole 作不变性检查，不以本轮推断放大倍数、生产质量或精确 kernel 根因。缺事件或模型不匹配按不签收处理，不调整样本找结论。
