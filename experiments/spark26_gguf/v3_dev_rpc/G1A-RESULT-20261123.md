- 候选源码、权重、镜像、启动参数和阶段均绑定到单次外层记录。质量进程在装载时、ready 和请求组之后记录模型可达驻留张量与 PyTorch CUDA allocator；独立可信客户端标记后两阶段并发送真实推理请求。标记目录只传阶段名字，候选只读，不含参考输入、受保护文件或账本。计时另起无驻留探针的容器。
- 先导冻结判据：以开发 E0 观测到的 2,048 B ready→post 存活分配差作为校准资料；采用 64 KiB 阶段容差、已校准基线 ±8 MiB 活跃分配范围。仅凭形状吻合或总量异常不证明它就是权重镜像；没有明确来源时按缺证处理。本负例同时具备精确候选源码中的显式反量化持久赋值和请求后真实 CUDA 张量库存。临时反量化不因经过该路径而失败。
- 工程边界：候选进程内探针用于可复现的模型库存观测，不是防任意候选代码篡改的硬件级证明。原生或不透明分配、特殊框架分配器、未覆盖形状另需独立证据；这项限制不用于放宽正式质量门。
- 共用 Pi 链随后记录了 114.598 节点秒的四场景开发计时，并用该 QKV-only 的**同一**制品和合法性回执进行了显式交付（质检+计时共 211.950 节点秒）。所有响应为脚本夹具，不是 Agent 自由探索；单个计时样本不能当作配对性能收益。
- 验收保留早期记录：[01](./g1a-01.json) 启动时诊断文件遮蔽 `gguf` 依赖，无有效质量回执；[02](./g1a-02.json) E0 开发校准，确认旧版“分配差必须为 0”的规则会对固定测试的 2 KiB 噪声缺证。随后锁规则，用新的容器执行 03，不合并这些轮次估计通过率。
