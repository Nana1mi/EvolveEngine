# Flash Max 引擎探索配置

`exploration.json` 登记 `p3-exploration-384k-v3`。一次运行从 E0/H0 开始，Engine 修改范围为 `GGUFLinearMethod.apply` 函数体。开发评测使用同期 E0、四场景测量器、G0/G1 和 Q8_0 驻留门禁。Agent 可在交付前测量和比较候选。首个具有有效质量回执、由 Agent 显式交付的候选立即结束会话，控制器关闭后续上游请求和开发 RPC。

| 层级 | 探索档生效值 |
|---|---:|
| 模型 | `deepseek-flash`，Thinking enabled，Max，SSE |
| Pi、Broker、出站请求单次生成 | 393,216 Token，含推理 |
| 本地登记上下文窗口 | 1,000,000 Token，含输入与输出预留 |
| 全程累计输入、输出 | 20,000,000 / 5,000,000 Token |
| 上游模型请求 | 最多 1,000 次 |
| API 费用准入上限 | ¥80.00，按高峰全未命中估价 |
| 墙钟、GPU 节点时间 | 各 12 小时 |
| 准许的开发评测 | 最多 200 次，另计启动时的一次同期 E0 |
| 单次 GPU 操作 | 360 秒，本地预留与签名 worker 上限对齐，按可信回执结算 |
| DeepSeek HTTP 读空闲 | 1,800 秒，发起请求时受剩余墙钟限制 |
| Pi 等待缓冲回复 | 该段启动时剩余墙钟加 15 秒，模型和开发工具使用原绝对截止时间 |
| 模型请求体、已验 SSE 回复 | 16 MiB，最大 193 MiB |
| Relay Unix Socket I/O | 模型路由使用 `relay_socket_idle_seconds`，当前 900 秒。工具路由为 390 秒 |
| 新 Pi 恢复次数 | 最多一次，生成截断与上下文换段共用 |

Broker 先用固定版本的公开 tokenizer 渲染计数，再加 `max(512, ceil(10%))` 作为本地输入预留。每个发出的请求保留完整的 393,216 输出额度。累计输出余量装不下一整轮时记录预算停止。上下文容纳不了输入和完整输出额度时，在出站前记录 `context_generation_window`。`read` 返回最多 8,192 字节及续读偏移。Relay 在 stdio 上等待已核验的宿主回帧，再向 Pi 分块转发。上游连续无数据时由宿主 HTTP 读空闲超时处理。Relay 等宿主回帧的 stdio 读取独立于 Unix Socket 的 900 秒 I/O 超时。

## 截断策略与费用记账

采用一次有界恢复。收到已结算的 `length`，或在出站前发现上下文装不下完整生成额度时，当前 Pi 清理结束后可开一次新 Pi。恢复从最后一个具有有效质量回执的候选与已激活的 Harness 开始，无合格候选时从 E0 恢复。`develop_quality` 通过即可成为恢复点，交付仍是独立的终止操作。新 Pi 接收简短交接。恢复点之后未经质量门验证的工作树改动、原对话和临时文件会随上一进程清理。两段共用绝对截止时间、剩余预算和费用账本。第二次达到恢复条件时结束。历史 P3 的两组按各自已登记的共同协议执行。后续正式 B0/B2 引入恢复时，两组应使用同一规则和额度。

每次出站前，费用门禁按高峰未命中输入 ¥2/百万 Token、输出 ¥8/百万 Token，为本地预留输入和完整输出额度计算人民币预留。余额不足记录 `api_cost_limit`。有回执时按实际 Token 用量以同一费率核算预算，无完整回执时保守扣账。用量超过本地预留时记录 `usage_uncertain`、扩大扣账并结束当前运行。2,000 万输入与 500 万输出按上述费率分别折合 ¥40 和 ¥40，合计 ¥80。该数值用于本地准入，供应商实耗和费用以账单为准。每次请求留存费率估算和缓存拆分，`api-cost-budget.json` 汇总两段的费用预算。费率查阅日期为 2026-11-24。[官方人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

## 速率与验收

2026-11-24 的两条已有实机回执均结算了 8,192 个推理 Token。窄任务第 10 次请求的 Broker 耗时为 52.438 秒，多轮测试第 13 次为 51.531 秒。含等待的有效速率约为 156.2 和 159.0 Token/s。按这两个速率外推至 393,216 个 Token，约需 41–42 分钟。这两条回执来自推理输出。正文输出速度和长上下文下的速度需另行测量。新账本记录首个及末个输出片段的到达时间，用于区分首输出等待和生成阶段。

`python p3_explore.py` 解析并打印配置。`python rehearse_exploration.py` 使用真实 Pi 1.5.2、模拟上游和模拟 GPU worker。离线验收覆盖 393,216 出站参数、202,374,558 字节 SSE、2,158,547 字节推理续传请求、首个交付后关闭上游请求、恢复合格候选与 Harness、清理质量门之后的工作树改动、上下文换段、恢复段费用预留不足的本地拒绝。模拟上游进一步验证了等待宿主回帧超过 1 秒时，配置为 1 秒的 Relay Socket I/O 限额仍可正常转发。

2026-11-24 的静默验收另用真实 Pi、Relay、Broker 和本机 HTTP 模拟上游。两组均出站 `max_tokens=393216`，Relay 模型 Socket I/O 超时均为 900 秒。模拟上游在前 1,205 秒不发送响应头或响应体：

| 宿主 HTTP 读空闲 | 结果 |
|---:|---|
| 900 秒（对照） | 900.068 秒以 `upstream_transport` 终止，Relay 无故障，按预留保守扣账 |
| 1,800 秒（探索默认） | 模拟上游静默 1,205.000 秒后回复，Broker 在 1,205.415 秒完成，Pi 正常结束，用量结算，Relay 无故障 |

结果区分了宿主 HTTP 静默超时和 Relay 等待 stdio 回帧的行为，没有测量真实供应商长生成速度。可用 `python rehearse_silent_upstream.py` 重跑默认组，加 `--upstream-idle-seconds 900` 重跑对照组。

实机入口显式接收 `--execute NEW_OUTPUT_DIR`，从专用 stdin 依次读取 API 密钥和节点认证，并复核固定源码、tokenizer、镜像、开发评测包和正负控回执。
