## 1. 来源与推理回传审计

查阅日期 **2026-11-23（香港）**：[DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[Token & Usage](https://api-docs.deepseek.com/quick_start/token_usage/)。API 页面未提供独立文档版号。API 明确区分 `high` 与 `max`；带 `tools` 的后续请求要完整回传此前的 `reasoning_content`，包括没有工具调用的助手轮。公开编码器的 `high=75` / `max=100` 是公开模型模板映射，不能从中推算托管推理开销。Token & Usage 将实际 token 数以模型返回为准，并提供离线 demo；未找到能在发送前证明该 hosted Chat 请求完整计费上界的公开契约。

- **Pi 1.5.2**（现有镜像、package-lock）从 SSE `reasoning_content` 累积 thinking block，以原字段名序列化回助手消息；profile 明确要求该字段。旧 Broker 拼接 SSE 片段，按工具调用 ID 比较推理内容摘要，匹配才放行；发送时不删改这个字段。r02/r03 已放行请求的匹配失败均为 0，r03 截断前最后一次验证了 5 个工具调用 ID。r01 的已放行请求通过了当时的校验，但被拒请求没有细分证据。没有证据表明漏传造成这几轮长推理。
- **覆盖缺口**：旧 Broker 不独立核验无工具调用助手轮的完整推理；P3 是一次 `--print` 会话，正常 `stop` 后不会继承原会话对话。候选增加有序的助手推理摘要核对，覆盖无工具轮及缺失、空值替代和内容变化。离线验收用拆分 SSE、实际 Pi 回传和篡改负例；不落推理原文。

## 2. 共用候选：输入计数、异常对账、分页读取

- 指定 [DeepSeek-V4.1-Flash-1017 公开资产](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017/tree/08c8657f02291e11b6f6b63e0e16014f8e748518)，revision `08c8657f02291e11b6f6b63e0e16014f8e748518`（`encoding/encoding.py` 与 `tokenizer.json` SHA-256 固定），计数运行库 `tokenizers==0.22.1`。按实际规范化出站 JSON 顺序，用参考模板渲染系统提示、用户/助手消息、工具 schema、工具结果和回传推理，再计该序列的精确 Token 数；离线候选登记余量 `max(512, ceil(10% × count))`。计数失败时不回退到旧的字节预留。
- **精确渲染计数 ≠ 托管用量的保守上界。** 公开权重、公开模板和 tokenizer 的版本已经固定，但托管服务可能采用不同包装、额外前缀或计费口径。登记余量只用于离线候选，不宣称能够保证付费硬上限。不把这个候选接到 live P3 或部署为预算门。若要继续办付费诊断，须先解决上界的证据，或让用户明确批准“本地预留是计划上限、供应商实耗可能超额”的不同风险口径。
- 对超过任一预留的响应，Broker 记录 `usage_uncertain`、供应商报告值和差额，每维按 `max(报告值, 预留值)` 一次计入保守账本，冻结 lease，不转发或重试。对账记录不冒充正常用量或成功答复。此机制能发现并拦住后续请求，但不能撤回已发生的上游用量。
- 双方使用同一个受版本锁定的 `read` 工具，单个 **JSON 工具结果 UTF-8 ≤ 8,192 字节**（含转义与分页元数据）。结果含 `content`、`truncated`、`next_offset`、`version`；偏移是从 0 起的 UTF-8 字节位置。续读提交 `expected_version`，文件变化报错并从头重读，不会静默截断或切开字符。按序拼接 `content` 不补换行。限制只针对默认 `read`，不是对 shell、自写工具或全部上下文的全局 I/O 限流；B0/B2 不增加不对称能力、摘要策略或工具权限。
- [离线回执](./launcher-context-candidate-01.json)：真实 Pi 在 `fixed_train` 和 `evolving_train` 中各读取四页，按字节无损重组同一 24,950 字节夹具（BOM、CRLF、中英文、emoji 与 JSON 转义）；四个工具结果为 8,071、8,078、8,079、3,009 字节。两臂各走完四次工具调用及一次 `stop`；无付费、无 GPU。回执记录源码/资产摘要和数值，不记录请求正文。

## 3. 2×2 诊断预登记提案，不是统计比较

**待批；未执行。** 每格一次明确限定的测量请求，不执行真正的 SGLang 改动、无自主多轮、无 GPU。因素为 `reasoning_effort ∈ {high,max}` × 同一个 `read` 工具结果的 `{约 38 KB 全读对照, ≤8 KB 首段}`。固定同一 `deepseek-flash` 指纹、系统/任务、工具 schema 和共同的历史框架；合成 UTF-8 源把目标函数和核验所需信息都放在共同前缀内，长条件多出的只是无关文本。冻结夹具字节、请求/证据哈希、发送顺序、参数与判定脚本后才可申请启动。合成历史要含匹配的助手推理和工具结果，不靠模型再产生一个不受控的读码轮。每格独立，无复用模型会话，无自动重试。

- **额度建议**：最多 4 次，输入本地预留计划上限合计 60,000（每格 15,000），输出计划上限合计 16,000，各格固定 `max_tokens=4000`（不超过单次 4,096，且四格有相同上限；不能四次都设 4,096，因为相加为 16,384）。任一格不能预留、指纹不符、用量不确定或稳定性检查失败就停并记原因，不把该格补跑为成功。调用次数和发出的 max_tokens 可在本地强制；计划上限不保证供应商实耗，见 §2。
- **主要结局**：首个有效行动为完整 `tool_calls`，且仅调用预定验证工具一次，参数通过固定 schema、目标文件/函数检查和合成正确性门禁。一个裸 `stop`、可见文本说要改、残缺调用或超出范围均不是有效行动；`length` 不执行工具。次要结局：结束类型、截止前推理用量、首个有效工具调用开始前的推理量（只有文本/字节可定位时，另报告参考 tokenizer 的局部计数，并与上游结算数分列；无法精确分摊就记不详，不能拿全轮值冒充前缀值）、请求及读码字节、输入/输出用量和状态。没有有效行动时，前缀计量按结束时截尾，不记成零。
- **判定**：且仅且有一格成功、其余均未完成有效行动且四格有可解释完整证据时，才考虑对该格做重复验证；这不是宣布 High 或分页优胜。四格均截断，就停止这条参数筛查路线，回到任务范围与接口；不加预算。多格成功或结果/证据混杂，记为不能区分，保留当前配置，不据此选型。若 High 后续被锁定，B0 和 B2 一起切换。

## 4. 关于放宽探索档

同意**独立且有硬停止条件**的探索可以回答端到端可行性与首次合法候选的成本，不同意直接放开或把各维一次乘十：r02/r03 截断时总资源还富余。若只是验证循环，缩小首个任务（明确函数范围、仅约束一个改动点，不给现成补丁）比直接更换模型或抬单次上限更直接。等计量放行后，至多一个独立探索档尝试；可讨论两会话合计 60 分钟墙钟、40 GPU 节点分钟、600k 输入、72k 输出和每次仍不超过 8,192 的外层上限，具体预算尚未获批。S1 交接失败则不启动 S2。若这次仍无合法候选，缩小任务范围，不重跑、不无限堆版本。任何输出只作工程可行性/成本观测，不计入正式 W 或 B0/B2 效应证据；没有完整 Episode 时也不把截尾实耗当完成成本。
