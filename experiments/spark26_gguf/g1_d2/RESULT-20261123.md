**决定：精确正控和本次混合取消检查通过；不冻结通用数值阈值，不开 G1-V。** 针对近并列的简单“Top-1 必须不变”有反例；反过来，数学形式相同也不能自动证明质量损失足够小。以下均为开发结果，没有打开独立位置或密封 Q/T。

## 核心观测

C 是真实的执行路径改变：在 Q8_0 块边界把 K=2048 一分为二，用原生算子计算两个部分积，FP32 相加再回到 BF16；没有向 logits 加噪声。**它是算式等价的对照，不是已获业务质量批准的“小误差”金标准**。部分积有中间舍入，整体计算路径也变了；没有逐层定位，不能把全部差异归为一种具体舍入机制。D 只交换两个通道，但这发生在命中快路径的层；代码改动局部不等于对最终分布影响必然小。D 的机制/幅度在观察结果前登记，没有加大故障来追求拒绝。

### Margin 为什么要和分布一起看

E0 margin 事前分层（近并列 ≤0.125；中间 (0.125,1)；较大 ≥1）：分别有 5、18、9 个位置。C 的翻转数分别为 2、2、0；D 为 3、5、1。

- 开发位置 **15**：E0 margin 0.0078125；C 和 D 都将原第一名 403 换掉，但 C 的 KL / TV 是 **0.00333 / 0.03329**，D 是 **0.04441 / 0.12035**。同样是翻转，不是同一种分布变化，也不能仅凭接近平票宣告 C 合格。
- 位置 **9**：E0 margin 1.09375；C 保留 Top-1，D 将 770 换为 12052，KL / TV **0.29635 / 0.27858**。这是预定义错误在非平票位置的语义反例。
- 描述性地用 E0 重启、B、C 在各层的 KL、TV、Top-10 差的最大值画范围，D 在近/中/大层分别有 5/5、8/18、3/9 个位置超出至少一项，另外 16/32 未超出。**这不是引擎漏检率**：一个引擎可以被多位置联合检出；单个位置也可能落在参考范围内。这个开发范围不是正式质量阈值。

## 补丁是否真正执行

r1 原始回执已用 7 个离线测试复核（含完整回放）。其 E0 / QKV 的源文件摘要确实不同，但 r1 没有逐请求快路径回执。另一次既有 shadow 归档本轮重新回放，见到 M=1、2、130、260、768、1536 六种形状的真实命中及位级等价检查；只作独立旁证，不回填 r1。

**本轮有同次证据。** B/C/D 各 32/32：真实计算后记录串行在途的请求 ID、输入摘要、实际 M、正在执行的模块路径与文件摘要；分别与启动清单、响应和本地冻结实现相符。观测版 B 是在原 QKV-only 基础上加探针，源码哈希不应等于未插桩版本。每次创建新容器，Python 字节码和指定 JIT 缓存用独立目录；固定镜像内的已有原生二进制继续复用，不声称全量重新编译，也未把带探针结果拿去计时。

## 混合取消是否伤及另一个请求

E0-A、E0-B、B 各自先单跑固定的 160-token 存活请求，然后同时发出它与另一个 128-token 上限的目标请求。分别在目标已有 8、32 个 token 时定向取消，共 **6/6** 次可验证。每次都核到目标 ID 与 `abort` 终态（实际结束于 11–12 或 35 token），同时核到存活请求在取消发出前已生成 7–32 token、取消 ACK 后仍生成并正常完成。六条存活序列与本机独跑、干净 E0 独跑的 **160 个 token 完全相同**。这三次启动的调度日志各有一条 `Decode batch, #running-req: 2`，是启动级旁证，不冒充每个请求对的 ID 日志。这里只签收禁用 radix cache 的两路混合样例，未检查页回收或所有并发负载。
