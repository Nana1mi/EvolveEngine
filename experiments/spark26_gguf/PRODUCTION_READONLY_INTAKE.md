# 星火 Q8_0 生产等效性：只读登记表（未签收）

用途：防止把已运行的 `.108` 诊断 E0 冒称为现网。**这里不是在在线实例上执行测试的指令。** 只从已获授权的发布清单、部署参数以及现成监控中登记。优先取已有摘要；如必须重新对 1.8 GB 文件求摘要，在授权的副本/发布制品上做，不在繁忙在线节点临时增加 IO。不要重启、跑性能剖析、发送测试/暖机请求、清缓存或更改设置。不要导出客户提示、token ID、密钥、完整环境变量或未经裁剪的生产日志。

| 必须登记 | 最低证据 | 当前状态 |
| --- | --- | --- |
| 服务版本 | 正在部署的 SGLang Git SHA，兼容层/本地补丁 SHA，容器 digest 或底层镜像 ID；能查时核对部署记录和实际导入出处是否吻合 | **待核**；`b2ce…` 是诊断 E0，不是任何在线实例证据 |
| 权重 | 实际 GGUF 的 SHA-256 和字节数，量化类型；模型 config、tokenizer 与 chat template 各自的摘要/清单 | **待核**；诊断用内部转换版，公版同名文件不同 |
| 运行形状 | 实际硬件（GPU/CPU、架构/driver）、每实例卡数与 TP/PP/DP；特别说明是否与 GB10 实验节点一致 | **待核** |
| 有效服务参数 | attention 后端（prefill/decode），两种 CUDA Graph，radix/prefix cache、上下文/KV 容量和 dtype、最大活动请求、chunking、调度策略、推测解码与产出长度设置 | **待核**；由 ops 提供脱敏后的有效参数，不照抄默认值 |
| 应用 API 行为 | 实际使用的入口、流式行为、thinking/工具模式与 parser、停止与错误语义、应用侧合批/重试政策 | **待核**；6 项诊断 API 检查不能替代业务验收 |
| 业务负载/SLO | 现成匿名聚合：采样窗口和分桶样本数、输入和输出长度、并发或到达率、共享前缀、工具/思考开关占比、若存在的 TTFT/TPOT/SLO | **待核**；没有生产样本时可继续用合成负载，但不能贴生产标签 |

填写时每项记录采集日期和发布/配置证据出处。保留原始内部材料在其权限边界内；实验仓库只保存摘要、已批准的聚合与等效参数。缺失项写明原因和影响，不能拿诊断参数补齐。只读资料齐备后，在已授权独占的隔离节点复刻，先核对实际镜像/权重/生效参数及质量，再按固定业务负载做 E0/E0。若硬件或负载不匹配，则继续作为实验室先导并明确差异。

## 交接方式

给已获授权的脱敏文件路径即可，不要求套固定格式；若尚未上线，注明“计划部署”。建议先交两小份材料：

1. **部署身份与设置**：镜像摘要和摘要类型（registry manifest 或 image config ID，不能混比）；SGLang 提交及本地改动摘要；GGUF SHA-256 和大小；模型配置、tokenizer/chat template、generation config 摘要；硬件/驱动与有效引擎配置。包含明确关闭项，不能把缺项当默认值。
2. **应用与负载**：入口及流式行为、thinking/工具是否使用、并发/到达统计、输入/输出长度桶及样本量、共享前缀、SLO 已有口径。未上线就标“计划/合成”，不可把压测或先导数据标为现网观察。

本地已有经授权的隔离服务启动日志时，可用 `python runtime_identity.py project <saved-log>` 生成字段白名单投影，或 `python runtime_identity.py compare <left-saved-log> <right-saved-log>` 做对照。它只读本机文件，无网络，不导出模型路径、地址、密钥或原始日志。`startup_args` 与调度器实际容量、KV pool 实际类型/容量分列；`None/auto` 原样保留，不靠默认值猜配置。投影是核对工具，不代替源码、镜像、权重、硬件、入口和负载的等效性证明。未授权的在线日志不应为使用这个工具而采集或转发。
