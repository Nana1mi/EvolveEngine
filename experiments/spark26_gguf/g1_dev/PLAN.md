# P1 开发门禁实机校准 r1（事前登记，不是正式 Q）

在旧四场景同一镜像/权重/配置上开四个独立容器：E0-1、E0-2、QKV-only、故意错误的 QKV（仅在该诊断容器中对融合结果取负，不进入训练材料和部署）。不计时、不训练、不访问密封 Q/T，不用付费模型。每种观察项单独记录，证据不足不判违规；有客观反例时单列原因，不让另一缺项掩盖已证实的错误。

- 在同一个聊天模板上以贪心、未指定 stop、允许自然 EOS 生成；约定原始 E0 两次重启必须相同，并且 finish=stop、matched 为模型配置的 EOS、未达到长度上限。比较候选 token、计数和原因。对本次声称精确等价的 QKV 参考与故障对照要求精确相同；不借此给一般 Kernel 设逐 token 硬门。
- 让一个带独立 request ID 的长请求生成若干 token 后，在同容器内只取消该请求。必须有在途 token、针对该 ID 的取消回执及终态/流结束。终态不清楚即证据不足。取消前后在同进程运行相同的两个不同哨兵请求，并与全新 E0 对照；这是取消后**可观察输出**隔离，不宣称所有 KV 页正确释放。prefix cache 仍禁用，不据此验收其开启时的行为。
- 两组固定合成前缀（130/260 token，对应 QKV 快路径），各采一个位置的**完整词表归一化 log-prob 分布**；不是未经归一化 logits。保存按词 ID 排序的完整 float32 向量，验证词数/有限性/归一化，计算 KL(E0||样本)、最大对数概率差、Top-1 及前二间距。不以 QKV 或坏版本结果事后选阈值。本轮只能校准稳定性与明显错误检出；两个前缀不能给任意浮点近似设最终容忍带。
- 旧四场景合成性能结果不入裁决。成功正控、拒绝故障、证据缺失时不签收，是三种不同结果。记录从启动到退出的节点耗费；不因此宣称 G1 其余部分（特别是所有分配驻留和并发条件）已通过。
