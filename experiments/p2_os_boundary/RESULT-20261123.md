# P2：真实 Pi 与独立外层的无 GPU 工程验收（2026-11-23）

[回执 03](./receipt-03.json) 同一 Linux Pi 1.5.2 夹具的 T1–T7 路径均有证据：**8 个独立 Agent 容器、54 个合成模型请求、102 个 broker 合成记账单位**，另有一次依赖漂移启动拒绝和独立 Judge。它验证的是桌面合成部署边界，不冒充生产签收或自主搜索。后续将这些机制接到了共用 Runner，见下一节。

| ID | 实际证据 |
|---|---|
| T1 | B2 训练真实 `write`、提交两个版本，由外层内容寻址存储；在激活坏版处冻结。C1/C2 实际从已冻结的字节加载、公布给模型、调用并获外层随机挑战，合法输入得 2。 |
| T2 | B0 训练能在会话内写、装、调用工具，但提交被拒；销毁后新 B 按名调用失败，只用相同事实重建再调用成功。 |
| T3 | B/C1/C2 启动的 E、事实、Pi/镜像、模型配置、资源限制相同。模型首请求逐项比了实际公共工具 schema、系统提示、用户消息、Max；随工具轮次逐次核验前一请求推理字段。这里的用量是合成的。 |
| T4 | C1 写只读快照被 Linux 拒绝，提交和切换指针被进程外 broker 拒绝。替换登记的合成依赖后拒绝启动。C1 的同会话修补仍真实调用成功。 |
| T5 | C1 的脚本/缓存/日志/会话/笔记五个私有标记可读；容器销毁后，后来另起的 B/C2 均不可见。C2 仍复现冻结的旧缺陷。标记检验为固定合成文件，不声明已覆盖任意真实 Pi cache 插件。 |
| T6 | Agent 非 root、无网络、无 Docker socket、只读基镜像；独立 broker 授权真实合成开发调用，并拒绝 Judge、密封数据、计量、工具和回执请求；可信文件未挂给 Agent，前后完整性摘要一致。另起干净 Judge 容器只读入单文件玩具 Engine，不挂 H、私有文件或 Agent socket。 |
| T7 | 坏版成功加载，失败用量保留；无显式请求保持坏版，有显式调用才回滚到好版。重新开训练会话验证返回 0，而后续冻结评估仍加载坏版、重现缺陷。 |
