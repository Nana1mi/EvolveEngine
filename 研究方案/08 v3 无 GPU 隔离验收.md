# v3.2 无 GPU 隔离验收表

**要判的事：** B2 能跨会话继承自建工具，B0 不能直接继承；两个组都能临场解决问题，但没有哪个评估分叉可以把新知识带进兄弟分叉。对应[设计 §5–6、§11](./07%20框架%20v3%20设计.md)。**先导范围的共用 Runner 已验收。** [P2 验收报告](../experiments/p2_os_boundary/RESULT-20261123.md) 链接 T1–T7 真实容器证据、共用 Runner 冻结轨迹、真实 Max 与实际 Spark Worker 开发回执。通过只限启动单的合成负载和单文件范围，不签收生产、W 或正式 RQ-A。 T3 已有[真实 Pi + 本地模拟模型的配对请求预检](../experiments/p2_cpu_wire/RESULT-20261123.md)；不是完整 V3 Runner 的 T3 回执。 T1/T2 新增[真实 Pi 工具恢复夹具](../experiments/p2_tool_restore/RESULT-20261123.md)：最终预登记的两次复测（05、06）均完成五会话；此前 01–03 未完成、04 完成，回执全部保留。目前不签收整项。 通过只说明被测配置下的工程对照成立，不是 RSI、性能收益或生产安全的证明。

## 1. 固定一条可以复核的轨迹

玩具仓库和事实库用合成内容；不挂 GPU、不用付费模型、真实密钥或正式 Q/T。模型响应、开发工具和裁判工作负载可以是确定性替身；签收时须使用登记的 Pi 与扩展加载路径、真实的会话隔离，以及独立运行的计量、开发工具服务和裁判。仅用同进程 mock 跑通可作预检，不能签收可信边界。

| 阶段 | 谁做什么 | 留作对照的对象 |
|---|---|---|
| 训练会话 S1 | B2 创建 `count_hits`：先提交正常版 H_good，再主动激活合法且可加载的 H_bad。输入有匹配时两版都正确；无匹配时应返回 0，H_bad 却报错。B0 的训练夹具也建一个同名临时工具。 | H₀ 从未内置该工具。外层保存两个 B2 版本和截止时的激活指针；B0 的临时副本没有持久版本。 |
| 冻结 | 在 H_bad 激活时截止，冻结为 H\*。用同一份玩具 checkpoint 和 W 事实库启动后续评估。 | 特意冻结坏版，不让 Controller 换回好版。A（无 W）不属于本次最小验收。 |
| 评估会话 C₁ | 从 H\* 恢复。先用有匹配输入证明继承的版本可调用，再用无匹配输入触发缺陷。只在私有空间修好副本，复测得 0，同时留下一个本分叉独有的合成标记。 | 三次调用分别绑定原版、原版、临时副本；错误和修复成本都保留。 |
| 评估会话 C₂、B | **在 C₁ 结束后**从原起点分别新建。C₂ 必须重现 H_bad 的错误；B 能读到相同事实，但在自行编写工具之前不能解析或调用 `count_hits`。 | C₂ 是 C 条件的工程复核，不是额外的独立统计样本。B 若现场重建后成功，不判失败。 |
| 训练期回滚对照 | 另用隔离的训练副本从 H_bad 出发：一次不请求回滚，一次由测试 Agent 显式请求恢复 H_good。此副本不回写已经冻结的 H\*。 | 验证的是“可自主决定”，不是要求真实 Agent 必须以这种顺序更新、必须回滚。 |

## 2. 逐项签收

每一行都需要**操作、预期现象和独立回执**。以下是七项完整验收规格；传输预检不替代其中任何整项。

| ID / 项目 | 操作 → 必须观察到 | 谁出具什么回执 | 一票否决例 |
|---|---|---|---|
| T1 · B2 持久化 | 销毁 S1 运行环境后启动 C₁；不重写工具，即可从 H_bad 加载、注册并成功处理有匹配输入。 | 外层安装器核对训练快照、挂载内容与实际加载身份；工具网关记录注册与真实调用的版本、输入摘要和结果。 | 只见文件或工具名，没见调用；实际命中的是基础镜像中同名工具。 |
| T2 · B0 隔离 | 销毁 B0 训练会话；新 B 可通过公共检索接口读到预置的同一条事实，但初始工具列表中无 `count_hits`，按名调用不可用。再让 B 在本会话重建并调用。 | 外层检索回执、启动时工具目录快照；网关记录重建前不可用、重建后成功及私有工具来源。 | B 直接获得旧工具或私有笔记；或为防继承而禁止 B 现场重建。 |
| T3 · 起点一致 | 在第一次 Agent 动作前比较 B 与 C₁/C₂：E、起点事实、W 事实库、检索策略、模型配置、基础提示/工具、Pi 及公共环境、资源上限相同。仅允许 H/M_H 及其引入的内容不同，运行 ID 等标识不计。 | 控制器出启动清单与逐字段配对差异；broker 和 RPC 侧核对生效配置、预算与首个受控请求。 | 基础工具或预算不同；两份 W 事实库同名、内容不同；把 C 专属提示记为公共提示。 |
| T4 · 冻结与依赖 | 核对 H、全部实际加载的依赖和配置后启动。C₁ 可修复本地副本；对公共快照的写入、提交新版本、更新激活指针这三项测试请求均须被外层拒绝。另换一个合成依赖版本作负对照：摘要不符应拒绝启动。 | 外层安装器记录启动前后及公共版本集合/指针摘要、有效依赖和 Pi 身份、拒绝回执；网关区分原版失败与临时副本成功。 | 只核 H 目录；依赖漂移仍开跑；文件未变但产生公共新版本或激活指针改变。 |
| T5 · 分叉隔离 | C₁ 的脚本、缓存、日志、会话历史和私有检索记录各带唯一标记；确认 C₁ 能读到，再在后启动的 C₂ 和 B 的 Agent 可见面逐项核对。C₂ 无匹配输入仍报原错。 | 外层记录各标记的阳性对照、独立工作区/缓存/历史/检索命名空间、后继可见面检查和 C₂ 原版调用回执。 | 任一标记进入兄弟分叉；C₂ 没修复就得到 0。外层审计留档允许存在，但不能对后继 Agent 可见。 |
| T6 · 可信外层 | 通过真实 Pi 加载登记的测试扩展，在合成资源上核对其权限：允许已授权的开发调用并独立记账；拒绝更改计量、受保护工具与回执、读取密封标记或调用最终裁判。仅由外层在干净 E 上运行模拟裁判。 | broker/账本给出成功与失败成本；权限边界记录授权/拒绝，外层独立复核资源摘要、密封标记未向 Agent 返回、裁判输入不含 H 或私有文件。 | 扩展与计量共用可写存储；不经授权就能改回执或读密封数据；唯一的拒绝证据是 `pi_guard.ts` 或扩展自报。 |
| T7 · 缺陷版本与自主回滚 | H_bad 合法并能加载；运行时报错仍记账。训练副本未请求回滚时保持 H_bad；仅在 Agent 显式请求后才恢复 H_good，并用同一失败输入验证恢复。评估快照仍是 H_bad。 | 安装器给出版本/指针时间线、发起者及请求 ID；网关/账本记录失败、恢复后结果和模拟成本。 | 外层按效果拒装合法坏版、静默择优、替 Agent 修复、抹掉失败成本，或回滚影响冻结的评估版本。 |

## 3. 证据与裁决

- 同一回执链以 `run_id / phase / session_id / fork_id / event_id` 串起快照、工具或请求、结果和成本。合成计量明确标为模拟单位，不报真实 token 成本或 GPU 时长收益。
- **loaded / available / invoked 分开记。** 安装清单只证明预期来源；实际加载需外层观测。若内容进入提示，broker 用实际请求与来源片段摘要核对；注册不是调用，失败调用也必须有回执。Agent 自报可作线索，不能签收。
- 每次执行填写 `测试 ID｜状态｜外层回执 ID/路径｜实际与预期的差异`。状态为未执行、通过、失败、证据不足。出现反例记失败；缺少独立回执记证据不足。**七项全部通过且版本清单一致，才能签收线 B**；修复后保留原失败记录及新一轮回执，不沿用旧配置的通过结果。
- 线 B 通过不能替代线 A 的 E0、业务负载、质量门和成本校准；两线分别验收后才进入小规模自由优化，不据此开启正式 RQ-A。
