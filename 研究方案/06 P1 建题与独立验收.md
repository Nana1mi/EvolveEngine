**当前：K28、K56、K71、K82 均已有出题侧证据，独立签收仍为 0/4，未放行盲跑。** 本页不是给被测执行器的提示词。依据 [05 §8](./05%20框架%20v2%20设计.md)，先验证题，再用题选执行器。未签收的题不能计作执行失败，也不能占用 16 次盲跑名额。

## 交付给谁

- 出题人和独立复核人使用本页。被测 Pi 的干净工作区只有允许编辑的引擎源码、**当次一张**任务卡和本臂允许的公开开发反馈；不要挂载本仓库、此目录、参考补丁、计数探针、验收回执或其他卡。两种执行器收到同一张卡的相同字节。收集提交与独立验收结束前，不向会话回传裁判结果。
- 如需参考实现、反例补丁或私有工作负载，在裁判端另存；版本库只记内容摘要及签收状态。P1 使用自己的开发与验收请求，不动 RQ-A 正式 Q/T、P2 留出池；探针运行与正式性能测量分开。
- 离线依据是本地 mini-sglang 源码 `9a91cfafe754aa85daee49998176275667eb58f2` 和本仓库 `2af59c2` 的运行器。前者**不是** GB10 部署凭据。锁定目标 SHA 后先复查下表入口；不命中就暂停该题，而不是把源码推测记成测量结果。

## 首轮四张候选卡与签收方法（K17/K43 现保留为未证实的历史版本）

| 单独下发的卡 | 出题理由（仅裁判可见） | 锁定机器上怎样证实或否定它 |
|---|---|---|
| [K17](./p1-cards/K17.md) | 局部正例候选。`scheduler/scheduler.py::_make_positions` 在 padded 请求上构造位置范围；单请求 decode 是否值得特化是待测假设。 | 参考补丁须改变命中形状的构造工作。对齐 prefill 和 decode 的位置、dtype 与输出；未命中形状保留原语义。过质量门后，在无探针运行中复测，过噪声线才签收。 |
| [K43](./p1-cards/K43.md) | 跨文件正例候选。`engine/engine.py::forward_batch` 每步建立 CPU 结果与完成事件；`scheduler/scheduler.py::_process_last_data` 同步后消费结果。不能仅凭 `.to("cpu")` 断定底层内存未固定。 | 参考补丁需实际改变生产和消费两侧的交接；检查相邻步、连续请求和末步的 token 未被提前覆盖。记录有效 token 数、资源建立/复用计数与质量回执，再单独无探针复测；若有效但测不出收益，不能当正例。 |
| [K28](./p1-cards/K28.md) | 语义负控。针对“只要看到 EOS 就停止”的具体假设，不是断言所有停止优化都不行。 | 预先选定一个 E0 实际会在长度上限前产生 EOS 的输入；让同一输入分别执行正常停止和忽略 EOS。保存逐 token、长度与结束原因。用“无条件在 EOS 结束”的反例补丁重放：正常停止对照正确，忽略 EOS 的回执确实少 token 或结束状态错误。若找不到见证输入或门禁未检出，题不签收。 |
| [K56](./p1-cards/K56.md) | 路径负控。`engine/sample.py::Sampler.sample` 的贪心分支直接 argmax；`sample_impl` 在另一个分支。公开性能运行器使用 `temperature=0`。 | 在裁判副本记每次请求的 `Sampler.sample` 与 `sample_impl` 调用数。锁定负载必须**采样调用数 > 0 而目标函数调用数为 0**；单独用非贪心诊断输入验证同一探针能记录 > 0（不改性能负载）。在 E0 和只改指定函数体的对照补丁上复验，并核实提交没有改变调用点。只凭 kernel 序列相同或耗时波动不能下这个结论。 |

> 以上 mini-sglang 路径均相对 `python/minisgl/`。K28、K56 考的是能否识别不成立的**具体假设**：如实拒绝/标未证实，与声称成功却未通过独立验收，必须分开记。若发现其他优化，按新候选登记，不能给本题记功。

## 上机签收顺序

1. **锁条件**：登记引擎完整 SHA、镜像/模型/部署配置/负载摘要、节点身份、质量门版本；登记裁判与出题人（不可同人）、参考补丁及回放脚本摘要、E0/E0 校准回执。占位配置或离线源码不能替代。事先登记比较块、顺序、重复数、噪声判线及边界读数的处置；不能测到显著为止。
2. **建题**：先拿到 E0 质量基线和两项负控见证，再对两道正例分别做最小参考补丁、逐题过质量门。在相同工作块、节点和环境上独立重复交错计时，保存原始回执，与预登记的 E0/E0 噪声线比较。开发计时、带探针计时均不作签收计时。
3. **独立签收**：未参与出题者从干净检出、按登记脚本重放。正例必须既忠实、质量合格，又有可分辨的重复收益；负控必须重现预登记的拒绝原因。失败或缺证据填原因，不替换成“参考作者没做出来，所以不可行”。
4. **止损与开跑**：建题限 1 工程人日、≤4 GB10 节点时；到顶没有两道合格正例就停在建题。四题齐签、同预算的两种执行器就绪，才启动 ≤8 节点时的 4 题 × 2 执行器 × 2 新会话（含 §8 所定复核成本，费用只记一次）。逐题报告“有无救回可复现失败、有无假成功、实耗多少”；不把 16 次会话当独立样本估成功率。执行器冻结后才能采 P2 数据。

**每题回执最小字段（空项不算通过）：** 卡 ID/正文摘要；部署与题集摘要；父引擎/参考补丁/裁判脚本摘要；重放命令及输入承诺；质量回执；正例的各块原始计时与噪声判线，或负控的见证输入承诺、预期与实测；独立复核人、结论、费用及原始事件索引。真正的私有输入和补丁留在裁判端，不附在公开任务卡中。
