# 02 实验协议与判定规则

本协议回答两个问题。在一个固定推理部署中，把有限算力用于自动更新候选排序，最终交付的引擎是否更快？把同一份引擎和历史记录交给两个已经冻结的 Harness，它们在接下来的半小时里能找到多大的增益？第一个问题计入发明、检验策略的成本，第二个问题识别已经学到的策略的作用。

以下数字都是**待校准的设计值**。当前笔记没有这套实验的运行记录。先导阶段只使用开发材料。锁定配置、划分、分析脚本、容器和预算后，生成带日期、内容散列的正式协议。先导链与正式链独立。固定部署下不同请求样本用于检验可复现性，结论的适用范围是本协议规定的部署和请求分布。

## 2. 工作负载、划分与正确性

**请求如何得到。** 先导可用确定性模板生成合成请求，例如由段落拼接、带数值的表项检索、代码片段续写三类模板生成不同正文。首轮离线用项目内新编的模板和确定性伪随机整数、标识符、属性值构造正文，不依赖本机其他语料或联网抓取。把模板正文、生成器源码、输入种子、tokenizer 修订、分层采样与 `requests.jsonl` 清单一并签名。先导中锁定三类比例和词表填充方法。先编码，按桶目标补足或截取普通正文 token，再添加已冻结的特殊 token，逐条断言总长度。按完整请求的 token IDs 去重，检查近重复模板实例及跨集合共享长前缀。相同分布允许共享模板。共享请求的缓存命中不能充当优化。正式结果须注明这是一种合成请求分布。

**性能语义。** 贪心解码，每条请求产生和传回全部 128 个 token，性能模式忽略自然 EOS 提前停止。任何生成步仍需计算完整词表的下一 token 分布，执行同一贪心选择。固定形状可以合法专门优化，但跳过推理、缓存预存答案、按请求指纹走捷径、减少有效词表或少返回 token 的候选不合格。测量器核对请求、返回 token 数、完成状态和逐请求时间戳。独立的自然 EOS 测试启用正常停止条件，核对结束 token 与 finish reason。若业务希望度量自然输出长度，另立工作负载并预注册，不混入本次分母。

| 请求/轨迹池 | 用途 | 可见范围与规模起点 |
|---|---|---|
| 公开搜索 `S` | 工具调试、分析、候选筛选和在预算内确定提交 | 开发者/Agent 可见，预生成至少 256 条请求，每个快速块 8 条，三桶 2/4/2。固定块规格，调用计费。开发者可提供公开正确性样例。 |
| 开发晋级 `D` | 固定裁判验证候选 Harness 对后续搜索是否有用 | 每个晋级机会使用新抽取的两个开发分叉和互不重复的 16 请求块（三桶 4/8/4）。允许返回汇总结果。开发裁判的数据和后续被测引擎不得作为正式样本。 |
| 独立因果库 `C` | 预先构造同任务的未见引擎快照和截至当时的经验 | 每条正式谱系另建一条 H0 探索链，独立种子，不向 `U0` 暴露。按第 0.5、1、2 小时预存引擎和经验。库内链不超过 2 卡时。每次续跑只拿到该快照的可见前缀和独立公开搜索块。 |
| 封存性能 `T` | 评估已提交引擎，计算净收益 | 每个比较单元准备 3 个独立的 64 请求块，每块三桶 16/32/16，分层打乱。候选与参照配对使用同块。搜索、晋级和调参完成前均无法访问。 |
| 封存正确性/质量 `Q` | 独立检查数值语义、自然停止及运行稳定性 | 按相同硬件、模型构造新的输入、解码前缀、边界长度、自然 EOS fixture。与 `S/D/T` 独立。正式批次封卷后才发布该池，开发阶段使用同结构的独立副本。 |

**种子与隔离。** 先导公共主种子 `11001`，正式公开搜索主种子 `21001`，开发晋级 `31001`，独立建库 `41001`。使用带版本的确定性生成器，从池名、复制号、阶段、块号、用途和主种子派生子种子。每对的运行顺序、请求顺序和工作器采样分开派生。配对内共享请求和可控的 Worker 随机数，独立复制号之间独立。`C` 的隐藏快照/轨迹和 `T/Q` 的生成再分别加入裁判持有的随机 256-bit 盐。正式前公布其散列承诺、请求清单散列、模板与数据划分规则，最后一次封卷后公布盐、全部清单和实际调用记录。Agent 看不到隐藏数据路径、散列至内容的映射和正式裁判返回。独立质量与性能裁判运行在只读评测镜像内，检查候选只改变允许的引擎文件。

开发晋级池 D 也加裁判私有盐，运行组只看到公开搜索块和准许披露的汇总。每个配对单元先固定同一套 T/Q 请求，再安排两个实验臂和参照的测量。评测时只有客户端读取完整请求表和预期结果，引擎进程只能收到正常服务接口送达的当前请求。正式结果在全部实验臂和检查点的交付版本锁定后统一揭盲。

**正确性与质量逐层检验。** 每层失败记录原因、token 位置和版本，开发环境提供定位信息，正式封卷后统一出报告。

1. 公共快速门。检查构建、启动、超时、OOM、完整返回、确定性和请求间 KV 状态隔离。检查首 token、跨若干 decode 步和不同输入长度。正式负载之外的边界请求只用于功能兼容性。
2. 全词表门。固定一个独立的可信 reference，在 teacher forcing 的同一 token 前缀上比较 prefill 最后位置和 decode 第 1、2、16、64、127 步的**完整**词表输出，检查维度、词表顺序、NaN/Inf、概率质量和 argmax。在同一精度约定下以 FP32 计算全词表 log-softmax 和 `KL(reference || candidate)`。先导默认每个位置 KL ≤ 0.001。reference 第一、第二名 logit 差 ≥0.05 时要求 top-1 一致，差更小时要求候选所选 token 距 reference 最大 logit ≤0.05。位置须逐一通过。质量样例建议 32 个前缀，各桶和近似并列均覆盖。测试模式的观测点读取正常执行路径，另用同一编译产物走实际接口进行黑盒比对。
3. 服务语义门。固定 16 条贪心敏感性较低、已由 `E0` 与 reference 预验的端到端样例，比较完整序列。另设 8 条自然 EOS / 最大长度 / 停止边界样例（包含至少一条会在上限之前产生 EOS 的 reference 样例），逐 token 检查输出与结束原因。固定 32 条有唯一参考答案的合成提取/算术小题，以同一解析器计分，候选正确题数至少达到 `E0` 同批正确题数。若 `E0` 自身出现明显数值、稳定性或地板效应，暂停并在预实验调整后重新封存。这些检查只覆盖声明的精度和质量范围。
4. 封存门。正式提交重新构建并执行独立 `Q` 的同类检查，使用独立输入和前缀，记录版本与二进制散列。通过后执行 `T`。正式开始前只在开发副本上用 `E0` 对 reference、`E0` 对 `E0` 校准阈值。另用故意截短 logits、少返回 token 或串 KV 状态的测试替身检验裁判确会判失败。所有阈值一经锁定，应用于全部组。

**抗噪声。** 运行时采集 GPU 温度、时钟、显存、功率和负载，记录原始块、预热和失败轮次。每个 64 请求块对“锁定引擎/原始参照”各跑两次，顺序由事前随机数选 `ABBA` 或 `BAAB`，相同请求、交叉顺序抵消漂移。块内以两次的输出 tokens 总数除以两次的计时总和算各版本速率，块间取对数比的均值。先导默认 `E0/E0` 对数比的绝对值 95 分位不超过约 1%，且持续的 GPU 抢占次数为零。未达到时先排查并延长区块或增加重复，再确定正式规格。性能重复用于提高测量精度。C 分叉盲评中，同一冻结环境、同一检查点的相同提交共享一份独立 Q 门和相对参照的 T 评分；若提交就是参照，各预定 T 块仍实测一次，成功才记相对参照为 1。参照无效和提交失败仍按预设规则单列。独立 E0/E0 噪声校准与 RQ1 不使用这一捷径。

## 3. 主链、开发晋级与独立分叉

**H0 与处理变量。** 单 Worker 接新会话时先取同一套 profile，包含主机调度、GPU 计算/访存、launch 空隙等可用观测。固定生成器依当前引擎、公开反馈和当前 Memory 接口列出候选（带动作、瓶颈标签、预计成本、风险、ID）。`H0` 依次按瓶颈匹配优先、预计成本低优先、预登记的类别序、稳定候选 ID 解开并列。候选池必须足够大才有排序的空间。先导记录候选数、中位可交换对数和约束后的合规率。两臂使用同一生成器、工具、经验读写接口、证据量上限、复测/停止规则和 best-valid 提交规则。不同轨迹可以自然产生不同候选池。可变策略只返回给定候选 ID 的排列，不能写引擎、造候选、增加工具调用或修改正式评分规则。

**引擎如何进入开发主线。** 先导先以 E0 对 E0 的交叉计时估计公开 8 请求块的噪声界 ε，取绝对对数比的第 95 百分位与 log(1.005) 的较大者。64 请求正式块的噪声界另行估计。对每个通过开发质量门的补丁，候选和在任主线在同一个新 8 请求块上各跑一次，先后顺序预先随机，一共两次计费。候选对数收益大于 2ε 时推进主线，低于或等于零时归档；处于 (0, 2ε] 时，有余额才在另一块倒序再测一对，要求两次收益均为正且平均值大于 ε。余额不足或复核未过均保留主线。开发晋级短续跑的两个块足够测试一对并接受清晰改进。第一个父引擎计时可同时作为本步公开基线，同一执行只记一次；profile 单列卡时。首轮主比较允许保留合法的退化分支，下一次尝试一律以在任主线为父。把探索分支作为下一次优化起点留给独立消融。

**D/C 分叉的相同输入与尝试。** 两臂从同一冻结快照开始；同一逻辑步只生成一份观测和候选池。两臂独立排序，首选是同一完整候选时，共用一次实现、忠实度审计、质量门、筛选/复测及主线决定，再分别写入带原始臂 ID 的经历。给生成器和实现器的记忆不含臂路径，请求块和运行顺序由配对步标识决定。首次选得不同时从该次实现起分开，即使后来引擎哈希相同也不重新共享搜索。预算资格按操作原上限检查两臂及其共同外层账户；逻辑成本各计一次、实付只计一次。不跨快照、复制或数据分区查缓存，也不共享 RQ1 主链。

| 层次 | 对比与实验单位 | 运行办法 |
|---|---|---|
| 主链端到端 | 每个独立复制号一对，固定排序对允许更新排序 | 两臂从相同 `E0,H0,M0` 开始，均可继承各自的引擎代码和成功/失败报告。固定组把同样资源全部用于继续优化。进化组在同样限额内尝试依轨迹生成、晋级排序策略。每对随机决定执行先后，并在各复制间平衡。 |
| 开发晋级 | 一个待发布 `H′` 与它的直接父 `H`，对两个开发快照各续跑一次 | 在相同 `E_d,M_d`、相同候选生成器下，冻结两种排序。每臂每个开发分叉限额 15 分钟。只根据开发分叉的合法提交在独立 16 请求块上的性能决定是否接受更新。 |
| 独立因果续跑 | 主链预算截止取进化组的最终 `H*`（成功晋级为零则为 `H0`）。每对配一个从未接触的库 `C` | 在早/中/晚每个快照上，分别将 `H0` 与 `H*` 装入相同 Worker，挂载字节相同的 `E_c,M_c` 快照和全新会话，同预算 `b`。分叉期间两者均冻结。各分支可自行更新工作引擎和会话内轨迹。分叉后续引擎和数据不回流主链或其他快照。 |

**更新触发和晋级。** 先导预设在主链累计墙钟约第 60、150 分钟各开放一次提案机会，每次最多一个候选策略。仅在预留的剩余卡时、tokens、计时块足以完成比较时启动。不足就记为跳过。提案列出被解释的训练轨迹、假设、可观察的排序变化及失效条件。校验允许的输入、动作集合和固定测试回放，拒收运行不确定、依赖隐藏 ID、硬编码具体代码补丁或触碰门禁的策略。验证使用未参与提案的两个开发快照，与父版本比较。四次短续跑各自提交的最终引擎均通过正式规格的开发正确性门，两个快照中各自的“子策略最终合法引擎吞吐 / 父策略最终合法引擎吞吐”均大于 1，且两对几何均值至少 1.02，再晋级。若同一 D 点的两臂交付相同引擎，只做一次独立 D 质量门，合格则该点记零、不作重复吞吐评分；失败则验证不通过。相等、打平、崩溃或验证无法完成均保留父策略。记录全部所提版本、父版本和接受/拒绝理由。晋级是成本有限的开发规则，两个样本和 2% 阈值不用于作论文推断。

**预算结算与提交。** 发生过的候选生成、重复/失败尝试、编译、回滚、性能筛选、元提案、开发分叉的父子试跑与评分全由对应主链付费。预制开发数据和环境建设如被多个复制复用，单列总价和摊销方式。开发专用引擎快照若由进化组额外生成，向受益组计费或按已登记次数摊销至每条进化链。压缩/检索使用的模型 tokens 同样入账。一次“计时块”指一个引擎版本、一个固定请求块的一次计时执行，换版本、换块或复跑都另计。分叉上限指搜索调用，裁判额外开发评分也从主链余量扣除。预算器为在途操作预留足够额度，模型调用设置最大输出。若达到硬限，终止在途动作并只保留截止前已完成门禁的 checkpoint。表明预算被哪一维先用尽。

`E0` 为每条主链预先验证的最佳起始版本。每次开发门和公开性能复核通过才可替换。每条分叉以其 `E_c` 为起始版本。预算的 1/4、1/2、3/4 与截止点无条件签名记录当时唯一 best-valid 引擎。资源提前耗尽则之后延用最后一个。选择者只能看公开/开发数据。一律先锁定提交 hash，再由裁判盲测。裁判不在多个候选中取测试最大值。试验正式计费结束后的 `T/Q`、独立建库和独立分叉消耗单列，分组同额。系统交付总成本另列这些开销，避免把研究性评估开销算成生产加速收益。

每次开发晋级的两个起点由控制器事先指定。可从独立 H0 开发链按预设时间截取引擎与记忆快照，并为各窗口预留不同的快照及评分请求。更新器提案前不能读取这些快照或其后续轨迹。开发库多链共用时按预先登记的链数分摊实际建库成本，折入受益组各自的限额。两个窗口都达到门槛才可能观察到两次有效更新。结果中按实际晋级数陈述，单次成功只支持该次更新。

## 4. 指标、估计与失败处理

在任一盲测块中，`P(E,w)=传回的输出 token 数 / 测量区间的实耗秒数`。基准归一化 `S(E;E_b)=exp(mean_w(log(P(E,w)/P(E_b,w))))`，每个块内使用上文的交叉重复。主链 `E_b=E0`，分叉 `E_b=E_c`。对未达目标者，在受限达标成本统计中按分配上限截断。对达到者记录首次公开签名的达标 checkpoint 的实际时间。5% 达标的时间以开发侧证据计量，正式 T/Q 仅评估各臂的最终提交和已登记参照。TTFT 取请求提交至首 token 的时长。每请求 `TPOT=(末 token 到达时刻−首 token 到达时刻)/(128−1)`。用毫秒及 p50/p95 报告，受限于单请求闭环，此处不外推线上饱和容量。

| 终点 | 配对统计量与判定 |
|---|---|
| 一级，等预算交付 | 每个复制 `i` 得 `d_i=log S(E_evolving,i;E0) − log S(E_fixed,i;E0)`。对独立复制取均值及双侧 95% 配对 t 区间，按 `exp(·)−1` 报告百分比。通过条件为平均优势点估计 ≥3% 且区间下限 >0%。 |
| 二级确认，排序策略归因 | 每个检查点得 `delta_ic=log S(E_H*,ic;E_c) − log S(E_H0,ic;E_c)`。先对同一复制内早/中/晚等权平均，再以独立复制为单位按同一方法估计。按一级、二级的固定顺序做正式确认。一级不通过时仍公布二级估计和区间，以机制线索解释。要同时主张系统净收益及可归因的策略收益，两级均需通过阈值。 |
| 次要过程指标 | 按预先指定的墙钟 0、1/4、1/2、3/4、1 各点锁定主线。实验封卷后用同一组公开开发请求重放这些快照及起点，得到标为 `S_dev` 的开发曲线。重放成本在研究评估账中单列，不能挑选提交或返回搜索。四维账本同时绘出或附表。报告 5% 合法加速目标的命中率、受限达标时间（未达标计到预算上限，给达标率与删失数）、第一个合法改进成本、去重率、合格候选数/已执行候选数、分类失败、分析/排序/编译/评测/元更新成本、吞吐/TTFT/TPOT、显存峰值。曲线未测时间段不作额外性能推断。 |
| 行为证据 | 相同可见状态与候选池上的父/子排序差异、首选翻转率、所选候选类型、对应的被执行动作及独立分叉收益。保留无人手改的代码/策略 diff、训练轨迹 ID 与逐次晋级证据。工具自动保留最佳合法版本时，`Final/Best-Seen` 仅作实现一致性检查。 |

**预算点与开发重测的实现口径。** 每条主链独立计时，预算点为 `floor(B_wall_ms × k/4)`（`k=0…4`），0 点固定为起点。主线决定的墙钟与候选哈希在写入经验前持久化；到下一控制步或封卷时，用不晚于边界的最后一次合法签入登记各点。恰在边界签入可计入；尚在编译、筛选或元更新时沿用旧引擎，早停后持平，超时后才确认的补丁不回填也不提交。真机用本臂从启动到决定的实际墙钟，预算资格仍同时检查逻辑费用；离线夹具以模拟毫秒代替。

控制器在搜索前登记本复制公开 8 请求块的哈希。独立裁判核验封包，并在全部预定 Q/T 比较之后，在 `S_dev` 上对 E0 和两臂预算点的每个不同引擎实测一次；同一份原始回执可对应多个相同快照，不能算作新增样本。以同块 E0 的吞吐作分母，不强制曲线单调，不用筛选读数填缺。重测不占两组主链预算，单列 `S_dev.cost`（已含在 `evaluation_cost` 内，不二次汇总），余额不足或实测失败保留状态与缺失值。`S_dev` 是次要开发曲线，不能用于选版、晋级或替代正式 Q/T。

**锁定失败的解释。** 无合法改进、超额、Agent 崩溃、超时、排序失败都留在原组，提交最后一个在截止前已签名的公开合法版本。正式提交在 `Q` 失败或在 `T` 因候选自身崩溃、超时、缺 token 而无法完成时，计为本次交付失败，归一化 `S=1` 代表回退到事前登记的唯一可部署起点（主链为 `E0`，分叉为事前登记、并在封卷后也通过正式门禁的 `E_c`），另报未回退的失败类型与比例。不能在看到盲测结果后另挑候选。合法但盲测变慢时保留实测 `S<1`。如有未解决的服务语义/数值错误，不宣称该版本可部署。封存门错误拒绝/意外通过由独立裁判审计。分叉开始前，裁判用与最终 Q 不重叠的独立准入样本 `Q_admit` 验证并锁定每个 `E_c`。准入未过时按预案改用 `E0`，同时恢复其初始记忆并标记阶段降级，两臂共享该起点。若已准入的参照在封卷后自身未通过 Q 或无法完成 T，则该检查点没有合法计时参照，预设该配对贡献为零，标记“起点终评失败”，单列该类频数与移除后的敏感性结果。若连共同 `E0` 都不合格，该批协议停止。同步报告封存门失败率差与逐对合法性，附上“任一失败提交均劣于任一合法提交”的配对胜负敏感性表。若归一化收益主要来自回退计分，结论限于带该回退机制的部署。

基础设施中断只按事前规则处理，例如设备掉线/全卡重启、任务调度器误终止。相同种子、环境和起点对整对重跑一次，保留原事件与费用，不将实验方法触发 OOM、编译超时归为外部中断。再次中断视为缺失，报告对数、原因及缺失对能改变结论的边界。除主要区间外给出配对中位数、逐对散点和按独立链重采样的区间作稳健性检查。测量重复、请求数、同链多个 checkpoint 和重复调用均不充作独立样本。

## 5. 样本量、消融与研究结论

**先导与经费。** 先导跑 4 个独立主链对，并在独立库的中期 checkpoint 做 4 个归因对，只验流程、噪声、预算和配对方差。主链上限 `4×2×4=32` 卡时，归因 `4×1×2×0.5=4` 卡时，建库上限 `4×2=8` 卡时，另计独立测量。若门禁、候选多样性、每链搜索规模或晋级流程根本无法工作，改造后重做先导，保留前次日志。

**正式样本量。** 用先导/独立小预试估算两终点的配对对数差标准差 `s`。因四对估值不稳定，取两者较大值，再与 0.05 的保守下限取大。先导只有中期分叉，正式锁定前优先补检早、晚阶段的方差，并保留上述保守下限。预设双侧 α=0.05、80% 功效、真正优势为 3%，正态近似所需对数为 `ceil(((1.96+0.84)×s/log(1.03))²)`。正式取该结果与 12 的较大者。正式锁定前用配对 t 的非中心分布复算并向上取整。此规划针对“差异大于零”的检验，点估计超过实际价值线的概率另受真实效应影响。以 `s=0.05` 为例，正态近似为 23 对。按非中心 t 分布计算使双侧 95% 区间下限高于零的概率，24 对约为 79.2%，25 对约为 80.9%。所以按这一下限规划正式实验取 **25 对**。12 对可作为经费受限的估计性方案。当 `s` 更大导致资源不足，应在揭盲前记录可支持的效应与预算，把不足样本的试验定位为估计性研究。正式过程中不查看组别效果以决定是否扩样。

每个配对的 GPU 预算上限分解为主链 8 卡时、建库 2 卡时、三组独立分叉 3 卡时。按方差下限取 `N=25` 时，主链 200、建库 50、独立续跑 75，共 **325 卡时**。经费若只够 `N=12`，三项共 156 卡时，报告为估计性研究。另加 `T/Q`、准入和开发曲线重放、基线校准、重跑和可选消融，按先导的实测秒数乘以规定次数申请。若仅有一张独占卡，这些卡时基本需要顺序排期。多个相同型号的卡则按卡 ID 配对并跨臂平衡。

| 消融或扩展 | 设计与允许的解释 |
|---|---|
| 策略版本 × 跨会话记忆 | 在预选同任务快照上完整运行 `H0/M∅, H0/Mc, H*/M∅, H*/Mc`。`M∅` 关闭跨会话记录与检索，保留当前请求、profile 及会话内新反馈。`Mc` 共享同一封存前缀与检索上限。给定读入状态时渲染过程相同。报告策略简单效应、记忆简单效应和交互。收益只出现在 `Mc` 时，结论限定为策略与记忆协作。 |
| 手写排序/随机排序 | 对同一候选池设手写强排序或随机排序的冻结策略，完整运行同预算分叉。注明手工规则依据与开发成本。统一生成、执行权限与评分，评估领域启发式和随机探索能解释多少收益。 |
| 动作回放与失败反例 | 在相同状态替换排序，记录选择发生变化的具体候选与机制。静态回放只能说明决策不同。对未执行的候选不能借已有轨迹推断收益，需另行实跑。重复出现的负迁移、排序没改变或元更新占满预算均列入分析。 |
| 可选外推与严格递归 | 其他模型、硬件和请求分布另立协议。严格递归另冻相同初始 `H0`、经验数据和更新预算，比较 `U0` 与自主产生的 `U*` 分别得到的子代 H，在未参与两种 U 产生/选择的快照与请求上评测子代。记录 U 谱系、子代改进与产生 U 的全成本。 |

| 正式观察 | 可报告的结论 |
|---|---|
| 主链和分叉均通过，质量合格，有自动策略版本和行为变化 | 在本部署、负载与预算下，持续更新排序获得系统净收益。独立分叉也支持已学习排序提高后续引擎优化能力。 |
| 主链通过，独立分叉未达判据 | 报告系统层收益与分叉区间。检查是否优势集中于单次引擎发现、某条轨迹或某阶段，策略贡献尚待辨别。 |
| 分叉表现好，主链未达判据 | 报告探索性机制证据与发生作用的条件。分别核算发明与晋级策略的成本和后续使用收益，再研究成本能否摊销。 |
| 点估计为正但区间跨零，或多次种子结果相反 | 报告精度、异质性和约束条件。不能由“不显著”推出等效。若要支持等效，须另设等效界值与设计。 |
| 均未达判据，或观察到退化 | 保留完整失败谱和区间，报告候选质量、排序变化、可用余量及开销。列出能在下一项实验区分的原因。 |

**交付记录。** 最少提供冻结协议和清单、每条链的 `E/H/M/U` 版本与散列、环境与预算账本、原始请求时序和门禁记录、拒绝及接受的补丁、候选/最终引擎、正式裁判出具的逐对数据与区间。正式结果表保留“待测”直到独立评估完成。

本文中的具体阈值、请求清单规则与预算属于新增实验设计。
